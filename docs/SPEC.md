## スコープ

MVPのゴールは「キャラを作って、方針を決めて、死ぬまで1人生を完走し、リザルトが出る」こと。見た目はテキストとグラフのみ。

| やる | やらない(第2弾以降) |
| --- | --- |
| 学歴4種・職業5種・実家の太さ5段階・住む場所3種・車の有無・体質・運の初期ガチャ | 世代継承(子どもと育休は第2弾で追加。DESIGN.md §15) |
| 価値観4軸をプレイヤーが設定 | (起業は第2弾で追加。DESIGN.md §18) |
| 方針4項目(随時変更可)と月ターンのオート進行 | 保険、相続税の詳細計算(マイホームは第2弾で追加。DESIGN.md §19) |
| 手取り率近似、生活費、4種の資産運用、年金、奨学金、失業給付、配偶者の収入、自己破産・生活保護 | 景気サイクル(不況は単発イベントのみ) |
| 隠しステータス5種と死亡判定 | リザルト画像、AI実況連携、視聴者投票 |
| 結婚(フラグ)を含むイベント65個 | UIの作り込み、キャラ・イラスト |
| 年間サマリー、リザルト、セーブ | ランキング、実績 |

後から足せるように、イベント・職業などのデータはJSON、ロジックはDOM非依存の純粋関数にする。

## 技術構成とディレクトリ

TypeScript + Viteの静的サイト。サーバーなし、保存はlocalStorage、ホスティングはGitHub PagesかCloudflare Pages。グラフはChart.js、テストはVitest。

```
life-sim/
  src/
    engine/          # DOM非依存の純粋関数。ここだけでテスト可能
      types.ts       # データ型
      rng.ts         # シード付き乱数(mulberry32)
      setup.ts       # 初期ガチャとキャラ生成
      step.ts        # stepMonth: 1ヶ月進める
      money.ts       # 収入・手取り・支出・投資・年金
      stats.ts       # 隠しステータスの変化
      death.ts       # 死亡判定
      happiness.ts   # 幸福度
      events.ts      # イベント抽選と効果適用
      result.ts      # リザルト・人生タイプ
    data/            # 調整用データ(コード変更なしで追加・調整)
      education.json
      jobs.json
      family.json
      region.json
      events.json
      balance.json   # 係数類をまとめる
    ui/
      screens/       # setup, main, event, yearSummary, result
      charts.ts
    main.ts
  scripts/
    balance.ts       # N人生を自動プレイして統計を出す
  tests/
```

- 乱数はすべて`rng.ts`経由にし、`Math.random`は使わない(シードで人生を再現するため)
- 係数類は`balance.json`に集め、調整でコードを触らない

## データ型

ゲームの状態は`GameState`ひとつにまとめ、`stepMonth(state, rng) => state`で進める。ステータスはすべて0〜100、価値観は-2〜+2。

```ts
type Education = 'junior_high' | 'high' | 'vocational' | 'university';
type JobId = 'sales' | 'office' | 'engineer' | 'parttime' | 'factory' | 'none';
type FamilyTier = 1 | 2 | 3 | 4 | 5; // 5=太い, 1=実家が借金持ち

type WorkStyle = 'regular' | 'normal' | 'overtime' | 'grind';      // 定時/普通/残業多め/激務
type Spending = 'frugal' | 'normal' | 'comfort' | 'lavish';         // 節約/普通/ゆとり/浪費
type Invest = 'deposit' | 'index' | 'stocks' | 'speculative';       // 預金/積立/個別株/信用・仮想通貨
type HealthCare = 'ignore' | 'normal' | 'active';                   // 気にしない/普通/意識高め

interface Policy { work: WorkStyle; spending: Spending; invest: Invest; health: HealthCare; }

interface Values {
  risk: number;      // -2 安定志向 .. +2 挑戦志向
  relation: number;  // -2 家族重視 .. +2 自由志向
  spending: number;  // -2 貯める派 .. +2 使う派
  work: number;      // -2 生活のため .. +2 やりがい
}

interface Stats { health: number; stress: number; skill: number; credit: number; relations: number; }

interface Assets { cash: number; index: number; stocks: number; speculative: number; debt: number; studentLoan: number; }

interface StudentLoan { interestFree: boolean; annualRate: number; monthlyPayment: number; }

interface Character {
  name: string;
  education: Education;
  job: JobId;
  jobYears: number;          // 現職の勤続年数
  familyTier: FamilyTier;
  constitution: number;      // 体質 0-100(高いほど病気になりにくい)
  luck: number;              // 運 0-100(隠し)
  married: boolean;
  retired: boolean;
  pensionMonths: number;     // 厚生年金の加入月数
  avgMonthlyPay: number;     // 年金計算用の平均月収
  previousJob?: JobId;       // 再就職の「前職に戻る」用
  studentLoan: StudentLoan | null;
  lastMonthlyPay: number;    // 直近の額面月給(失業給付用)
  region: 'metro' | 'city' | 'rural';                     // 大都市/地方都市/田舎
  spouse: 'fulltime' | 'parttime' | 'homemaker' | null;   // 共働き/扶養内パート/専業
}

interface GameState {
  seed: number;
  rngState: number;          // 乱数の現在位置(セーブから同じ人生を再開するため)
  startAge: number;          // 開始年齢
  eventHistory: Record<string, { count: number; lastMonth: number }>; // once/cooldown用
  month: number;             // 開始からの経過月
  ageMonths: number;         // 年齢(月単位)
  character: Character;
  values: Values;
  policy: Policy;
  stats: Stats;
  assets: Assets;
  adaptedSpending: number;   // 慣れた生活水準(月額)
  achievement: number;       // 達成感の蓄積 0-100
  happinessHistory: number[];// 月ごとの幸福度
  flags: Record<string, boolean | number>; // イベント用
  log: LogEntry[];
  pendingEvent?: PendingEvent;
  dead?: { cause: DeathCause; ageMonths: number };
}

type DeathCause = 'illness' | 'overwork' | 'accident' | 'old_age';

interface LogEntry {
  month: number;
  ageMonths: number;
  type: 'event' | 'choice' | 'policy' | 'year_summary' | 'death';
  id?: string;
  text: string;
  snapshot: { netWorth: number; health: number; happiness: number };
}
```

`LogEntry`は第3弾のAI実況連携でそのままJSONとして流せる形にしておく。

## 月次処理の順序

`stepMonth`は以下の順で1ヶ月を処理する。イベントで選択肢が出たら`pendingEvent`をセットして止まり、UIで選ばれたら`resolveChoice`で効果を適用して再開する。

1. 年齢・経過月を+1。65歳になったら退職処理(`retired=true`、退職金を加算)
2. 収入: 給与(退職後は年金)を手取りにして`cash`へ。失業給付・配偶者の収入もここで足す
3. 支出: 生活費と健康費を`cash`から引く
4. 投資: 余剰の積立と、各資産の月次リターンを反映
5. 資金ショート処理: `cash`がマイナスなら投資を売却、それでも足りなければ`debt`に計上(節約しても暮らせない収入なら生活保護)。借入上限を超えた状態が6ヶ月続いたら自己破産
6. ステータス変化: 方針・年齢・ストレスによる増減
7. イベント抽選: 条件を満たすイベントから最大1件。選択肢があれば停止
8. 幸福度を計算して`happinessHistory`に追加、慣れの更新
9. 死亡判定。死んだら`dead`をセットして終了
10. 12ヶ月ごとに年間サマリーを`log`に追加し、UIは年間サマリー画面を挟む

方針の変更はUIからいつでも可能。変更時に`log`へ`policy`を記録する。

## 初期値データ

初期ガチャは学歴・職業・実家の太さ・体質・運をランダムに決める。価値観と方針はプレイヤーが設定する。職業は学歴に関係なく等確率。5種目の職業は製造(工場)を仮で入れた。

### 学歴(education.json)

| 学歴 | 出現率 | 開始年齢 | 初任給係数 | 昇給係数 | 奨学金(借金) |
| --- | --- | --- | --- | --- | --- |
| 中卒 | 5% | 15歳 | 0.80 | 0.85 | なし |
| 高卒 | 30% | 18歳 | 0.88 | 0.90 | なし |

## お金の計算

金額は円の整数で持つ。

### 収入

```latex
\text{額面年収} = \text{職業の基準年収(年齢)} \times \text{学歴係数} \times \text{働き方係数} \times (0.9 + 0.2 \times \text{スキル}/100)
```

- 額面年収にはさらに昇進などで変わる倍率 `flags.payMul`(初期値1)を掛ける
- 月給 = 額面年収 ÷ (12 + ボーナスの月数)。会社員はボーナスが年4ヶ月分(製造は3ヶ月分、バイトはなし)で、6月と12月に半分ずつ出る。無職(`none`)は収入0
- 額面年収には住む場所の給与係数も掛ける
- 失業給付: リストラされたら職業に関係なく6ヶ月間、直前の額面月給の60%を受け取る(非課税)。リストラされるかは職業のリストラ率 × 不況中3倍 × 運補正
- 配偶者の収入: 結婚時に配偶者の働き方を抽選する。本人が65歳になるまで続き、結婚後は変わらない

| 働き方 | 確率 | 配偶者の手取り(月) | 本人の手取り | 退職後の配偶者分の年金(月) |
| --- | --- | --- | --- | --- |
| 共働き | 35% | 18万円 | そのまま | 基礎年金 + 厚生年金6万円 |
| 扶養内パート | 35% | 8万円 | 配偶者控除で+5千円 | 基礎年金 |
| 専業(扶養) | 30% | 0 | 配偶者控除で+5千円 | 基礎年金 |
- 手取り率は額面年収の帯で決める: 300万円未満0.80、600万円未満0.77、1,000万円未満0.73、それ以上0.68
- 年金生活中の手取り率は0.90

| --- | --- | --- | --- | --- |

### 支出

- 生活費は収入に連動する(家賃込み): 生活費 = (最低限 + (自由に使える手取り − 最低限) × 0.85 × 支出係数 + ボーナス × 0.7 × 支出係数)× 物価。最低限は単身8万円・既婚12万円に住む場所の生活費係数を掛けたもの(家賃の差)。自由に使える手取り = 毎月の世帯の手取り(ボーナスを除く) − 決まった支出(車の維持費・健康費・実家への送金・親への仕送り・奨学金・ローンの返済)。ボーナスで使うのはボーナスの額まで
- 普通・節約なら、最低限の生活費を払えるかぎり月々の収入を超えない。浪費(×1.2)だと少しずつ赤字になる
- 月の支出 = 生活費 + 決まった支出
- 借金(カードローン・リボ)には年15%の利息がつく。毎月、残高の3%(最低1万円)を預金から自動で返し、さらに余剰があれば優先して返済する。繰上げ返済の方針なら預金で一括で返す
- 生活保護: 金融資産を使い切り、節約しても収入(年金を含む)で暮らせない月は、不足分を生活保護で補い借金にしない。受け始めると車を手放す。受給中は支出係数を「節約」に固定し、医療費(健康のための出費)はかからず(医療扶助)、幸福度の「安心」を0にする
- それ以外の不足は借金になる。借入上限は max(200万円, 額面年収の半分)。超えた月に警告を出し、超えた状態が6ヶ月続いたら自己破産(借金0、信用0、ストレス+30)。破産後7年はブラックリストで、借りられず支出は「節約」に固定、その間は再び破産できない(不足は延滞として借金に残る)

### 投資

余剰(手取り − 支出)のうち50%を「投資に回す分」とし、投資の配分(預金・積立・個別株・信用/仮想通貨を10%刻みで合計100%)どおりに振り分ける。方針で「毎月決まった額」(万円)を選んだときは、余剰によらず毎月その額を、配分の積立・個別株・信用/仮想通貨の比(預金の分は使わない)で買う。預金が足りない月は預金にある分だけ買う(第5回のUI見直し)。預金の分は現金のまま。繰上げ返済の方針なら、投資に回す分で先にローン → 奨学金を返す。各資産の月次リターンは正規分布で引く。

| 方針 | 対象 | 期待リターン(年) | 変動(年) | 特殊ルール |
| --- | --- | --- | --- | --- |
| 預金 | cash | 0.1% | 0 | なし |
| 積立 | index | 5% | 15% | なし |
| 個別株 | stocks | 6% | 30% | なし |
| 信用・仮想通貨 | speculative | 6% | 60% | 毎月0.3%の確率で暴落(-60%) |

```latex
r_{\text{月}} \sim N\left(\mu/12,\ \sigma/\sqrt{12}\right)
```

方針を変えても既存の保有資産はそのまま持ち続け、新しい積立の配分だけ変わる。

(第2弾)積立・個別株・信用/仮想通貨は、資産の画面からいつでも売って預金にでき、預金でまとめて買うこともできる。全部・半分・金額(万円)を選ぶ。元本は売った割合だけ減り、ログに `policy`(id: `sell` / `buy`)で損益・税金とともに残す。

(第2弾)**NISAと特定口座**: 毎月の積立も、まとめ買いも、NISAの枠から先に使い、超えた分は特定口座になる。

- NISAの枠: 1年でつみたて枠120万円・成長投資枠240万円(暦の1月に戻る)、生涯1,800万円(成長投資枠は1,200万円まで)。売った元本の分だけ生涯の枠が空く
- 積立はつみたて枠 → 成長投資枠、個別株は成長投資枠だけ。信用・仮想通貨はNISAに入らない
- 特定口座で売ると、利益に20.315%の税金がかかる(損のときはかからない)。NISAは非課税
- 足りないときの自動売却は特定口座から先に売る(税金のぶん多めに売る)。手で売るときは「特定口座から先に / 特定口座だけ / NISAだけ」を選べる
- 年間の収支に「投資の利益にかかる税金」を出す

### ローン

- 結婚式・新車・中古車(36回)・車の買い替えは「ローンで払う」を選べる。年3%、60回の元利均等で毎月返済(決まった支出に入る)
- それ以外でも、30万円以上の出費で預金と投資を合わせても足りないときは、足りない分を自動でローン(60回)にする
- 審査: 信用30未満、または自己破産後のブラックリスト中は通らない。返済負担率も見る: ローンの毎月の返済の合計が額面の月収(引退後は年金、無職は0)の25%まで、バイトは15%まで。起業の元手は創業融資として信用だけを見る
- 審査に通らないローンの選択肢は、理由(「審査に通らない(収入に対して返済が大きすぎる)」など)を出して押せない。自動のローンが通らなければ、足りない分はカードローン(借金)になる
- 自己破産するとローンも消える。純資産からはローンの残高も引く

### 性別(第2弾)

- 初期ガチャで男女を半々で引く。給料は男女で同じ
- 寿命: 女性のほうが長い(死亡率 男性×1.4・女性×0.7。平均寿命の差は約6年)
- 配偶者は同い年の異性とみなす。死別は配偶者の性別の死亡率で起きる。配偶者の働き方は、男性なら共働き30%・パート40%・専業30%、女性なら共働き94%・パート4%・専業2%
- 女性本人が出産すると健康が下がり、会社員なら育休を取らなくても産後2ヶ月は産休(額面月給の67%)

### マイホームと住宅ローン(第2弾)

- 会社員(28〜50歳、既婚だと起きやすい)に「マイホームの検討」が来る。頭金1割で買う / フルローンで買う / 賃貸のまま
- 買う家は年収の6倍まで(最低1,000万円)で、地域の相場(大都市5,500万・地方都市3,500万・田舎2,500万円)が上限。頭金と諸費用(7%)は現金で、足りなければローン
- 住宅ローンは最長35年・年1%、80歳までに返し終わる。審査: 信用30以上、年収の7倍以内、会社員か社長(バイト・無職は通らない)
- 持ち家は家賃がいらない(最低限の生活費の6割を家賃とみなす)。代わりに住宅ローンと、固定資産税・修繕(家の値段の年1.2%)がかかる。住宅ローン控除(残高の0.7%を13年)で手取りが増える
- 家の時価は純資産に入る(大都市は横ばい、地方都市は年1%・田舎は年2%下がる)
- 借金が借入上限を超えたら、破産の前に家を売って返す。収入だけでは暮らせなくなったら、生活保護の前に家を売る。自己破産すると家は競売
- 持ち家で転勤になると単身赴任(住む場所は変わらない)。持ち家だと引っ越しイベントは起きない
- イベント: 家の修繕(買って10年後から)、自然災害
- 金額・確率は DESIGN.md §19

### 起業(第2弾)

- 会社員(25〜55歳)で挑戦志向(価値観が中間より挑戦寄り)の人にだけ「起業のチャンス」が来る(挑戦志向が強い・スキルが高いと起きやすい)。小さく起業(元手300万円)/ 大きく起業(1,000万円)/ 続ける。元手が足りなければローン
- 社長の収入は役員報酬 = 基準額(小さく30万円・大きく50万円/月)× 業績。最初の業績は0.6(赤字に近い)。厚生年金に入る。ボーナス・退職金・失業給付はない
- 起業から1年ごとに決算。業績はスキル・運・働き方(激務ほど伸びる)・不況で上下し、0.35を下回ると廃業(整理の費用 100万 / 300万円)して無職に戻る
- 会社のイベント: 大口の取引先(業績×1.25)、社員が辞める、資金繰りの危機、買収の打診(業績2.5以上。売ると会社の価値を受け取って無職に)
- 社長には定年がない。65歳からは「引退を考える」(年に1回まで)で引退して事業承継するかを選び、75歳になったら必ず事業承継する。事業承継では会社の価値の半分を受け取る
- 社長には昇進・ボーナスカット・リストラ・再雇用など会社員向けのイベントは起きない
- 金額・確率は DESIGN.md §18

### 子どもと育休(第2弾)

- 結婚すると「子どもを考える」イベントが来る。望むと妊娠しやすくなり(年齢が上がると下がる、不妊治療もある)、10ヶ月後に出産。3人まで
- 出産で「自分が育休」「配偶者が育休(共働きのとき)」「取らない」を選ぶ。育休は1年で、給与の代わりに額面月給の67%(半年)→50%(半年)を受け取る
- 児童手当: 3歳未満1.5万円、高校生まで1万円、3人目からは3万円
- 子どもの生活費と教育費は年齢と方針「子どもの教育」(公立中心 / 私立中心)で決まる。大学に進めば22歳、進まなければ18歳で独立
- 生活費と公立の学校・塾の費用は世帯の収入で増減する(収入が少ない家庭は少なめ、多い家庭は多め。0.6〜1.3倍)。子どもの費用の9割は親が自分の生活費を削ってまかない、1割が貯金から出る
- 子どもがいると人間関係が上がり、小さいうちは自由時間が減ってストレスが増える
- 金額・確率は DESIGN.md §15

### 年金と退職

- 65歳で会社員は定年退職し、退職金を受け取る。バイトには定年がなく、65歳から年金をもらいながら同じ給料で70歳まで働き続ける
- 退職の直後に「再雇用で70歳まで働く / 引退する」を選ぶ(65歳時点で職に就いていた人だけ)。再雇用中は年金に加えて、退職前の額面月給の50%の給料(手取り率は通常どおり)が入り、働き方は定時扱い
- 基礎年金 = 月6.6万円 × min(1, 加入年数/40)。加入年数は開始年齢から退職までの年数
- 厚生年金 = 平均月収 × 0.005481 × 加入月数 / 12(バイトは0)
- 結婚フラグがあれば配偶者分として基礎年金を2倍にする(簡略化)。共働きの配偶者はさらに厚生年金月6万円

## ステータス変化と死亡判定

### 毎月のステータス変化

| 要因 | 健康 | ストレス | スキル |
| --- | --- | --- | --- |
| 定時 / 普通 / 残業多め / 激務 | 0 / -0.05 / -0.3 / -0.6 | -1 / 0 / +1.5 / +3 | +0.1 / +0.2 / +0.35 / +0.5 |
| 健康: 気にしない / 普通 / 意識高め | -0.1 / 0 / +0.3 | 0 / 0 / -0.5 | - |
| ストレス70以上 | -0.3 | - | - |
| 40歳以上 / 60歳以上 | -0.05 / -0.1 | - | - |
| 退職後 | - | -1 | 0 |
| 浪費(支出) | - | -0.5 | - |

- 体質の補正: 健康の減少量に (1.5 − 体質/100) を掛ける
- 平常値への回帰: 表の増減に加えて、毎月 健康 += 0.03 × (平常値 − 健康)、ストレス += 0.03 × (30 − ストレス)。健康の平常値 = 65 + 0.4 × (体質 − 50) − 0.4 × max(0, 年齢 − 40)。これがないと健康が0か100に張り付き、平均寿命が約68歳になる
- 無職中はストレス+1/月(働き方は定時扱い)
- 人間関係は毎月-0.1で自然に下がり、イベントや結婚で上がる
- 信用は借金があると毎月-0.5、なければ+0.1
- 全ステータスは0〜100にクランプ

### 死亡判定

```latex
q(\text{年齢}) = \min\left(1,\ 0.00014 \cdot e^{0.085(\text{年齢} - 20)} \cdot e^{0.06 \max(0,\ \text{年齢} - 85)}\right)
```

```latex
p_{\text{月}} = \frac{q}{12} \times 2^{(50 - \text{健康})/15} \times \text{行動補正}
```

- qは年間の基本死亡率の近似(20歳で約0.014%、80歳で約2.3%。健康補正を急にしたぶん、バランス確認で0.0003から下げ、イベントで病気・過労死が増えたぶん0.00017から0.00014に下げた)。後で生命表のJSONに差し替えられるようにする
- 85歳を過ぎると死亡率の上がり方が急になる(実際の生命表に近づける。100歳で約2.5倍)
- 健康補正: 健康100で約0.1倍、50で1倍、0で約10倍(健康が悪いと倒れやすい)。健康が良いことで下がる効果は80歳から15年かけて弱まり、95歳でなくなる(健康が悪いことの害はそのまま)
- 行動補正: 残業多め1.15、激務1.5、ストレス70以上でさらに1.2
- これとは別に、年齢に関係なく足されるリスクがある(死因はそれぞれ決まる)
  - 過労死: ストレス70以上で激務なら毎月0.015%、残業多めなら0.003%(死因は過労。若くても起きる)
  - 大病: 治療中は毎月0.1%、治療しないままなら毎月1.2%(死因は病気)
- 死亡時の死因は重みで抽選する

| 死因 | 重み |
| --- | --- |
| 病気 | 年齢 × (100 − 健康) / 50 |
| 過労 | 激務なら40、残業多めなら10、それ以外0 |
| 事故 | 10 × (1.5 − 運/100) |
| 老衰 | 85歳以上のみ、(年齢 − 80) × 5 |

## 幸福度の計算と人生タイプ

毎月の幸福度(0〜100)は6要素の加重平均。重みは価値観で変わる。

```latex
H = \frac{\sum_i w_i s_i}{\sum_i w_i}
```

| 要素 | 満たされ具合 s(0〜100) | 重み w(v = 価値観) |
| --- | --- | --- |
| 生活水準 | 下の式(絶対額 + 慣れとの差)。cは健康費・送金を除いた実質の生活費 | 1 + 0.25 × v.spending |
| 安心 | 100 × min(1, 金融資産 / (月の生活費 × 24))、借金があれば-30 | 1 − 0.2 × v.risk − 0.2 × v.spending |
| 人間関係 | 人間関係ステータス、結婚中は+15 | 1 − 0.25 × v.relation |
| 自由時間 | 働き方の自由時間(退職後90) | 1 + 0.25 × v.relation − 0.15 × v.work |
| 健康 | 健康ステータス | 1 |
| 達成感 | 0.5 × スキル + achievement | 1 + 0.2 × v.risk + 0.25 × v.work |

重みは最小0.2にクランプする。

### 生活水準(頭打ちと慣れ)

```latex
s_{\text{生活}} = 60\left(1 - e^{-c/200000}\right) + 40 \cdot \frac{1 + \tanh\left(2(c/a - 1)\right)}{2}
```

- c = その月の生活費、a = `adaptedSpending`(慣れた生活水準)
- 毎月 a ← a + (c − a)/24 で約2年かけて慣れる
- 絶対額の項は月20万円あたりから頭打ちになり、上げた直後は相対の項で一時的に上がる

### 価値観の変化

イベントの選択肢ごとに`valueShift`を持ち、選ぶたびに該当の軸が±0.1動く(-2〜+2にクランプ)。

### リザルトと人生タイプ

- 生涯幸福スコア = 月ごとの幸福度の平均(0〜100)
- 最終資産 = 金融資産 − 借金 − 奨学金の残高(死亡時点)
- 人生タイプは2軸の4象限。しきい値は`balance.json`で調整

|  | 最終資産 2,500万円以上 | 2,500万円未満 |
| --- | --- | --- |
| 平均幸福度 52以上 | 勝ち組人生 | 貧乏だけど幸せ型 |
| 52未満 | 金持ち不幸型 | 苦労人型 |

## イベント

### 定義の形式(events.json)

```json
{
  "id": "proposal",
  "category": "life",
  "title": "プロポーズのチャンス",
  "text": "付き合って3年の恋人が、将来の話を切り出してきた。",
  "conditions": { "ageMin": 22, "ageMax": 50, "flags": { "partner": true, "married": false } },
  "baseProb": 0.02,
  "probMods": [ { "stat": "relations", "above": 60, "mul": 1.5 } ],
  "once": false,
  "cooldownMonths": 24,
  "choices": [
    {
      "label": "結婚する",
      "effects": { "cash": -2000000, "stats": { "relations": 15, "stress": -5 }, "setFlags": { "married": true, "partner": false }, "achievement": 5 },
      "valueShift": { "relation": -0.1 }
    },
    {
      "label": "まだ早い",
      "effects": { "stats": { "relations": -10 } },
      "valueShift": { "relation": 0.1 }
    }
  ]
}
```

- 抽選: 毎月、条件を満たすイベントの確率 = baseProb × probModsの積 × 運補正。運補正は良いイベント(`good: true`)が (0.8 + 0.4 × 運/100)、悪いイベント(`good: false`)が (1.2 − 0.4 × 運/100)。当たったものが複数なら確率で重み付けして1件だけ発生
- 選択肢がないイベントは効果を即適用してログに残し、オート進行を止めない
- effectsで使えるもの: `cash`、`cashMonthsOfPay`(月給の何ヶ月分)、`stats`、`setFlags`、`addFlags`、`mulFlags`、`job`、`achievement`、`assetShock`(資産を一律何%変動)、`inheritance`(実家の太さに応じた相続)
- 選択肢は `outcomes` で確率分岐できる。条件(`employed` `retired` `minInvested`)、`probMods` の対象(価値観・フラグ・年齢・方針)、リストラの確率を職業データから取る `probFrom` の形式は DESIGN.md §7.1
- リストラは職業の月次リストラ率をイベント確率として使う(別に判定しない)
- achievementは毎月-0.2ずつ減衰する

## 画面構成

スマホ縦画面でも遊べる1カラムのレイアウト。メイン画面を中心に、イベントと年間サマリーはモーダルで重ねる。

| 画面 | 内容 | 操作 |
| --- | --- | --- |
| タイトル | 新しい人生、続きから、シード入力 | 開始 / ロード |
| キャラ作成 | ①生まれ(アイコンのカード)②あなたが決めること ③この人生の見通し | 引き直し、タイプ(価値観)、初期方針、方針を変えて見通しを見直す |
| メイン | 年齢、職業、手取り月収、金融資産、ステータスのバー、資産推移グラフ、直近のログ | 再生/一時停止、速度(1x/4x/16x)、次のイベントまで、方針変更 |
| イベント(モーダル) | イベント文と選択肢 | 選択肢を選ぶ |
| 年間サマリー(モーダル) | 年齢と経過年数、健康状態、金融資産と前年比 | 次の年へ(自動で閉じる設定も可) |
| リザルト | 享年、死因、最終資産、生涯幸福スコア、人生タイプ、資産と幸福度の推移グラフ、年表 | もう一度、同じシードで再挑戦 |

- 1xは1ヶ月あたり約1秒。16xなら1人生(約700ヶ月)が約45秒+イベント停止時間
- 運は表示しない(隠し値)
- 1年ごとにlocalStorage(`lifesim.save.v1`)へ自動セーブ。リザルト到達でセーブを消し、過去の人生記録に追加

## テストと受け入れ条件

### 単体テスト(Vitest)

- 同じシード・同じ選択なら、同じ人生(死亡月・最終資産)になる
- 手取り率の帯、年金額、退職金の按分が表のとおりに計算される
- ステータスが0〜100、価値観が-2〜+2を超えない
- 条件を満たさないイベントは発生しない。`once`は1回しか起きない

### バランス確認(scripts/balance.ts)

ランダムなキャラと方針で1,000人生を自動プレイし、以下を出力する。

| 指標 | 目安 |
| --- | --- |
| 平均寿命(全方針ランダム) | 78〜85歳 |
| 激務を続けた場合の平均寿命 | 全体より5歳以上短い |
| 最終資産の中央値 | 1,000万〜4,000万円(家の時価を含む純資産) |
| 4つの人生タイプの割合 | どれも10%以上 |
| 1人生あたりのイベント数 | 40〜90回 |

目安から外れたら`balance.json`と`events.json`の数値だけで調整する。
